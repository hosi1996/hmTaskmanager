# تصمیم‌های معماری (ADR کوتاه)

| # | تصمیم | دلیل |
|---|-------|------|
| 1 | Fastify + Prisma (JavaScript ESM، بدون مرحله‌ی build) | سبک، سریع، کانتینر کوچک؛ مهاجرت به TypeScript بعداً ممکن است |
| 2 | SvelteKit (SPA با `ssr=false`) + Tailwind 4 + adapter-node | باندل کوچک؛ پنل پشت لاگین است و SEO نیاز ندارد |
| 3 | نشست سمت سرور در Redis (کوکی httpOnly + SameSite=Lax)، نه JWT | امکان «خروج از راه دور» و قفل فوری؛ CSRF با هدر سفارشی `x-requested-with` |
| 4 | هش رمز با argon2id (`@node-rs/argon2`) | باینری آماده برای Alpine (musl) |
| 5 | 2FA (TOTP) با پیاده‌سازی داخلی RFC 6238 | بدون وابستگی اضافه |
| 6 | ایزوله‌سازی دسترسی در `lib/access.js`: `visibleTasksWhere()` فیلتر Prisma می‌سازد | مشتری هیچ‌وقت ردیف غیرمجاز را از دیتابیس نمی‌گیرد (نه فقط UI) |
| 7 | بات تلگرام = سرویس مجزا با long-polling؛ فقط به API داخلی `/internal/bot/*` (توکن مشترک) وصل است | نیازی به وب‌هوک/گواهی نیست؛ `/internal` از Nginx عبور داده نمی‌شود. دانلود فایل و ارسال پیام تلگرام در بک‌اند انجام می‌شود |
| 8 | PostgreSQL و Nginx موجود روی سرور استفاده می‌شوند؛ شبکه‌ی داکر `hmtm-net` مجزا | عدم تداخل با سرویس‌های دیگر |
| 9 | شناسه‌ها UUID v4 (`@default(uuid())`)؛ نام فایل‌های آپلودی = UUID خارج از مسیر public | الزام پروژه |
| 10 | هر دامنه‌ی بک‌اند یک پوشه‌ی `modules/<name>/routes.js` (فرانت: `lib/` + `routes/`) | افزودن قابلیت بدون دست‌زدن به بخش‌های قبلی |

## نقش‌ها
- **سیستمی:** OWNER (همه‌چیز) / STAFF / CLIENT
- **پروژه:** VIEWER < REPORTER < CONTRIBUTOR < MANAGER
- Viewer/Reporter (و هر مشتری غیر مدیر) فقط تسک‌هایی را می‌بینند که سازنده/اساین/دنبال‌کننده‌شان هستند. Contributor کارمند و Manager همه‌ی تسک‌های پروژه را می‌بینند.

## مسیر توسعه‌ی بعدی
Webhook خروجی/API عمومی (توکن API در جدول جدید + همان `access.js`)، PWA، اعلان ایمیلی (SMTP)، جستجوی کامل‌تر با `pg_trgm`/tsvector.
